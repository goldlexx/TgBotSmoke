# TgBotSmoke на Cloudflare

Отдельные ресурсы: Worker `tgbot-smoke`, D1 `tgbot-smoke-db`
(`0368b28f-dc56-464c-a8a9-b6db823ea14d`), Cron каждую минуту.
Другие Workers, DNS-записи и тарифы не изменяются.

Адрес: https://tgbot-smoke.rustik-yuldashev.workers.dev/health
Webhook: `/telegram`. `goldlexx.ru` не найден среди зон доступного аккаунта;
после предоставления доступа можно подключить `smoke.goldlexx.ru` как Custom Domain
и заменить URL в `scripts/ops.py`. Зона и платные услуги автоматически не создаются.

## Реализация

Исходная локальная Python-версия сохраняется; медицинские тексты и названия оценок
синхронизированы с облачной. Облачная версия работает
на JavaScript: Web Fetch API вместо aiogram/aiohttp, D1 вместо синхронного sqlite3,
Cron вместо APScheduler. Python Workers существуют, но требуют совместимых pure
Python/PyEmscripten зависимостей; перенос Windows venv не поддерживается.
Для небольшого бесплатного Worker выбран штатный JS runtime без Python/Wasm.
Документация: https://developers.cloudflare.com/workers/languages/python/packages/

Расчёты используют decimal.js с точностью 28, ROUND_HALF_UP при выводе.
Temporal проверяет ввод местных дат; расписание использует кэшируемый Intl/IANA,
проверенный против Temporal на переходах DST. Часть настроек и исходных ссылок
экспортируется из Python через `scripts/export_assets.py`. Этапы восстановления
и ежедневные факты Worker находятся в `src/health.js`. Тест сверяет расчёты
Worker с Python, в том числе суммы в нескольких валютах.
Сохранены регистрация, редактирование, FSM, достижения, подтверждения срывов и меню.

Cron выбирает только индексируемые `users.next_due_at` в UTC и головы очередей.
После отправки вычисляется следующий местный день, с учётом DST: пропущенное
весной время сдвигается вперёд, повторённое осенью используется один раз.
Изменения пояса/времени и выключение отменяют старые повторы; `/start` не включает
выключенную рассылку. Просроченная очередь не отправляет сегодняшний отчёт раньше
выбранного местного времени. Cleanup индексирован, ограничен 200 строками в час.

Действие, FSM, отметка update_id и ответы в outbox сохраняются одной транзакцией.
Сбой до commit возвращает 503; после commit повтор webhook не повторяет действие.
Cron и webhook используют одну блокировку пользователя. Лизинг отправки сохраняется
до HTTP-запроса; 5xx/таймаут допускают максимум две попытки всего, 429 — четыре.
Exactly-once между Telegram и D1 недостижим: после неоднозначного таймаута или
аварии после приёма сообщения возможен один повтор. Успешные ответы удаляются
из очереди сразу. Ошибка answerCallbackQuery или снятия клавиатуры не отменяет действие.

Для соблюдения CPU Free Cron делает до 8 защищённых HTTP-вызовов того же Worker:
каждый `/internal/delivery` получает отдельный CPU-бюджет. Нужен флаг
`global_fetch_strictly_public`; сервисная привязка не даёт такого разделения.
Сам диспетчер использует максимум 14 подзапросов с обслуживанием, доставка — 7.
Реальные замеры и ограничения: [AUDIT.md](AUDIT.md).

Новый пользователь видит приветствие и начинает регистрацию кнопкой «🚭 Начать».
Четыре шага: последняя сигарета → привычка → цена пачки → часовой пояс. Можно
выбрать «Сейчас», «Сегодня», «Вчера» или ввести дату и время, а на последнем шаге
выбрать город с UTC-смещением либо ввести другой город или часовой пояс. «Назад»
и «Отмена» доступны при ручном вводе вместе с выходом в главное меню. Повторный `/start` продолжает черновик,
а для действующего профиля показывает прогресс без изменения настроек.

После регистрации бот показывает меню и прогресс. Ежедневный отчёт по умолчанию
выключен. Чтобы подключить его, достаточно выбрать один из шести пресетов или
ввести своё время, например `6:00`. «Не сейчас» оставляет рассылку выключенной
и без расписания. В настройках можно отдельно подключить отчёты, изменить время
или отключить рассылку. При изменении времени состояние подписки сохраняется.
Следующий слот учитывает уже обработанный отчёт за местную дату и показывается,
когда облачная обработка активна. Обновление применяется без миграции профилей.

Остальные параметры доступны в настройках. Отметка срыва требует подтверждения и сохраняет
время и количество сигарет. Статистика по-прежнему складывается из бездымных
периодов. Рубеж поздравления резервируется до отправки и учитывается один раз
на профиль. После неоднозначного сбоя отчёт повторяется без поздравления.
`/privacy` объясняет хранение,
`/delete` с подтверждением удаляет профиль, серии, достижения, FSM и очереди.
Остаётся HMAC-метка ID с временем удаления для отсечения старых событий.
Ключ WEBHOOK_SECRET нужен для этой метки: при ротации сохраните совместимость
меток, иначе старые события после удаления нельзя будет распознать по прежнему хешу.
Резервные копии удаляются владельцем отдельно; D1 Time Travel Free — до 7 дней.

Публичный `/health` не показывает пользовательские данные. Логи выключены;
обработчики не логируют URL Telegram, токен, тела запросов или исключения.
BOT_TOKEN, WEBHOOK_SECRET и OWNER_CHAT_ID загружаются только через Wrangler Secrets.
Локальный webhook secret лежит в игнорируемой папке `private/`.

### Прогресс и утренний отчёт

«Мой прогресс» и `/morning` показывают одну и ту же шкалу из десяти сегментов.
Процент округляется и остаётся ниже 100 до рубежа. На границе открывается новый
участок. После 365 дней продолжаются годовые участки без новых наград в коллекции.
Подробная статистика показывает общее время без сигарет, оценки по всем сериям и
полученные достижения. Суммы в разных валютах отображаются отдельно. Эквивалент
жизни — статистическая оценка, пояснение и исследование доступны в «Как считаем».

Ручной и автоматический отчёты используют общий шаблон. Факт выбирается на начало
локального дня, мысль дня — из существующего каталога. Поздравление дополняет
обычный отчёт с текущей серией и шкалой следующего участка. Источники о здоровье
доступны через «Восстановление». `/start` прикрепляет новое нижнее меню, прежняя
кнопка «Моё здоровье» продолжает открывать раздел восстановления.

### Статистика для владельца

В личном чате с ботом отправь `/admin`. Worker сверяет положительный числовой
Telegram ID отправителя и чата с секретом `OWNER_CHAT_ID`. Чтобы включить команду,
владелец запускает `npx wrangler secret put OWNER_CHAT_ID` из папки `cloudflare`
и вводит подтверждённый ID в закрытом интерактивном поле. Без подходящего секрета
команда игнорируется. Она отсутствует в общедоступном меню Telegram.

Первые две строки показывают число записей в `users`. Запись создаётся при
завершении регистрации. Подписки считаются по `enabled=1`. При активной облачной
обработке те же профили допущены к автоматическим отчётам, включая профили без
`next_due_at`, для которых Cron восстанавливает расписание. Это показатель допуска,
а не числа немедленных или гарантированных доставок. Начиная с 200 профилей в
ответе появляется напоминание о проверке пропускной способности. Команда читает
только агрегаты и отправляет ответ через штатный outbox.

## Данные и переключение

`scripts/backup.py` использует SQLite backup API (включая WAL), сохраняет копию,
SQL и счётчики в игнорируемой `backups/`. Экспортируются users, streaks,
achievements, reports и fsm; импорт сохраняет ключи и значения без преобразований.
Начальная копия уже импортирована. `ops.py verify` сравнивает все строки всех
пяти таблиц с локальной базой. Не перезаписывайте действующую облачную базу
старой локальной копией.

Рабочая установка уже переключена на webhook и активна. Далее описан порядок
первоначального переноса для сопровождения; повторно выполнять его на действующей
базе не нужно. До первого переключения `cloud_control.active=0`: Webhook возвращает
503, Cron не отправляет сообщения. Порядок первоначального переключения:

1. Согласовать момент с владельцем. Остановить локальный бот (Ctrl+C), отключить
   его автозапуск. Не запускать `start.bat` после переключения.
2. Выполнить `ops.py verify`. Если данные изменились после начального импорта,
   сделать свежий backup и повторить импорт в неактивную D1; затем сверить строки.
3. После согласования создать локальный файл `cloudflare/private/cutover-approved`.
4. Из корня запустить `.venv/Scripts/python.exe cloudflare/scripts/ops.py activate`.
   Скрипт проверяет отсутствие Python-процесса бота и совпадение данных, делает
   новую резервную копию, включает Cron и вызывает setWebhook с секретом,
   max_connections=1, drop_pending_updates=false. При ошибке выключает активность.
5. Проверить `ops.py status`, `/health` и отправить боту `/start` из Telegram.
   Ожидающие сообщения сохраняются (Telegram хранит обновления до 24 часов).

`ops.py` привязан к аккаунту владельца, конкретной D1, URL Worker и Windows.
Для другой установки сначала адаптируйте эти значения; это не универсальный CLI.

Нельзя запускать локальный polling одновременно с облаком: он удаляет Webhook.
Для отката сначала выключить active в D1, сделать экспорт D1 и перенести актуальные
данные обратно; затем deleteWebhook без удаления pending и локальный запуск.

## Обслуживание

Из `cloudflare/`: `npm ci`, `npm test`, `npm run deploy`.
Из корня: `.venv/Scripts/python.exe -m unittest discover -s tests -v`.
После изменения Python-текстов повторить `scripts/export_assets.py` и тесты.
Wrangler deploy не переключает Webhook и не меняет флаг active.

Используются только Workers, D1 и один Cron без платных дополнений.
На Free действуют общие квоты аккаунта: 100 000 запросов/сутки,
5 млн прочитанных строк D1/сутки, 100 000 записанных строк/сутки,
5 GB хранения, CPU 10 ms на вызов. Cron отправляет максимум 8 задач в минуту;
остальные переходят в следующие тики. HTTP-вызовы доставки дополнительно расходуют
квоту запросов Workers. Бесплатный тариф не даёт гарантии SLA; замеры на 200
профилях не подтверждают лимиты для произвольного объёма истории и нагрузки аккаунта.
Документация: https://developers.cloudflare.com/workers/platform/limits/
и https://developers.cloudflare.com/d1/platform/pricing/.
