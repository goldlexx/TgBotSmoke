# TgBotSmoke на Cloudflare

Отдельные ресурсы: Worker `tgbot-smoke`, D1 `tgbot-smoke-db`
(`0368b28f-dc56-464c-a8a9-b6db823ea14d`), Cron каждую минуту.
Другие Workers, DNS-записи и тарифы не изменяются.

Адрес: https://tgbot-smoke.rustik-yuldashev.workers.dev/health
Webhook: `/telegram`. `goldlexx.ru` не найден среди зон доступного аккаунта;
после предоставления доступа можно подключить `smoke.goldlexx.ru` как Custom Domain
и заменить URL в `scripts/ops.py`. Зона и платные услуги автоматически не создаются.

## Реализация

Исходная локальная Python-версия остаётся без изменений. Облачная версия работает
на JavaScript: Web Fetch API вместо aiogram/aiohttp, D1 вместо синхронного sqlite3,
Cron вместо APScheduler. Python Workers существуют, но требуют совместимых pure
Python/PyEmscripten зависимостей; перенос Windows venv не поддерживается.
Для небольшого бесплатного Worker выбран штатный JS runtime без Python/Wasm.
Документация: https://developers.cloudflare.com/workers/languages/python/packages/

Расчёты используют decimal.js с точностью 28, ROUND_HALF_UP при выводе.
Temporal проверяет местные даты, DST и смещения. Тексты, клавиатуры, медицинские
этапы и ссылки экспортируются из оригинала `scripts/export_assets.py`.
Тест сверяет полный отчёт с Python, включая валюты, округление и приветствия.
Сохранены регистрация, редактирование, FSM, достижения, подтверждения срывов и меню.

Уникальный `(user_id, local_date)` резервируется до отправки. Успех, пропуск,
неизвестный результат, блокировка и отклонение не повторяются. Только явный 429
переходит в `retry`; пауза сохраняется в D1 и переживает перезапуск. При смене
расписания retry не удаляется. Вебхуки проверяют секретный заголовок, сохраняют
update_id, используют блокировку пользователя в D1. `max_connections=1`
сериализует входящие сообщения; Cron использует ту же блокировку.
При аварии после резервирования возможен пропуск вместо повторной отправки —
как в оригинальной версии. Exactly-once между Telegram и D1 недостижим.

Публичный `/health` не показывает пользовательские данные. Логи выключены;
обработчики не логируют URL Telegram, токен, тела запросов или исключения.
BOT_TOKEN и WEBHOOK_SECRET загружаются только через Wrangler Secrets.
Локальный webhook secret лежит в игнорируемой папке `private/`.

## Данные и переключение

`scripts/backup.py` использует SQLite backup API (включая WAL), сохраняет копию,
SQL и счётчики в игнорируемой `backups/`. Экспортируются users, streaks,
achievements, reports и fsm; импорт сохраняет ключи и значения без преобразований.
Начальная копия уже импортирована. `ops.py verify` сравнивает все строки всех
пяти таблиц с локальной базой. Не перезаписывайте действующую облачную базу
старой локальной копией.

Рабочая установка уже переключена на webhook и активна. Далее описан порядок
первоначального переноса для сопровождения; повторно выполнять его на действующей
базе не нужно. До первого переключения `cloud_control.active=0`: Webhook возвращает
503, Cron не отправляет сообщения. Порядок первоначального переключения:

1. Согласовать момент с владельцем. Остановить локальный бот (Ctrl+C), отключить
   его автозапуск. Не запускать `start.bat` после переключения.
2. Выполнить `ops.py verify`. Если данные изменились после начального импорта,
   сделать свежий backup и повторить импорт в неактивную D1; затем сверить строки.
3. После согласования создать локальный файл `cloudflare/private/cutover-approved`.
4. Из корня запустить `.venv/Scripts/python.exe cloudflare/scripts/ops.py activate`.
   Скрипт проверяет отсутствие Python-процесса бота и совпадение данных, делает
   новую резервную копию, включает Cron и вызывает setWebhook с секретом,
   max_connections=1, drop_pending_updates=false. При ошибке выключает активность.
5. Проверить `ops.py status`, `/health` и отправить боту `/start` из Telegram.
   Ожидающие сообщения сохраняются (Telegram хранит обновления до 24 часов).

`ops.py` привязан к аккаунту владельца, конкретной D1, URL Worker и Windows.
Для другой установки сначала адаптируйте эти значения; это не универсальный CLI.

Нельзя запускать локальный polling одновременно с облаком: он удаляет Webhook.
Для отката сначала выключить active в D1, сделать экспорт D1 и перенести актуальные
данные обратно; затем deleteWebhook без удаления pending и локальный запуск.

## Обслуживание

Из `cloudflare/`: `npm ci`, `npm test`, `npm run deploy`.
Из корня: `.venv/Scripts/python.exe -m unittest discover -s tests -v`.
После изменения Python-текстов повторить `scripts/export_assets.py` и тесты.
Wrangler deploy не переключает Webhook и не меняет флаг active.

Используются только Workers, D1 и один Cron без платных дополнений.
На Free действуют общие квоты аккаунта: 100 000 запросов/сутки,
5 млн прочитанных строк D1/сутки, 100 000 записанных строк/сутки,
5 GB хранения, CPU 10 ms на вызов. Cron обрабатывает максимум 3 доставки за
минуту, остальные обрабатываются следующими тиками. Для личного бота этого
достаточно; бесплатный тариф не даёт гарантии SLA или неограниченного масштаба.
Документация: https://developers.cloudflare.com/workers/platform/limits/
и https://developers.cloudflare.com/d1/platform/pricing/.
